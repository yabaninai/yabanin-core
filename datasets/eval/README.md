# Public synthetic evaluation fixtures

These Apache-2.0 project-authored inputs are deterministic regression examples,
not production traffic or a representative benchmark. They contain no customer
records, operational credentials or private evaluation data. Credential-shaped
strings are inert synthetic markers; card numbers are synthetic checksum examples.
Attack instructions are test data and must never be executed. The first attack
sentence retains a marker already present in the public tamper test.

| File | Purpose and coverage |
| --- | --- |
| `golden_routing.jsonl` | 32 authored rule-tier cases: 10 easy, 10 medium and 12 hard. Includes keyword priority, case folding, code fences, length and tool-shaped text. |
| `routing_baseline.json` | Expected class snapshot for the same 32 IDs. The tests check exact membership and agreement with the authored labels. |
| `guards_labeled.jsonl` | 24 detection cases: four positive and four negative controls each for secret markers, card checksums and injection phrases. |
| `routing_example_set.v1.json` | The same 32 routing cases exported through public dataset preparation and example-set APIs. |
| `attack_text_cases.v1.json` | 36 authored cases: eight per attack class (prompt injection, secret leakage, tool abuse) plus 12 benign controls, distributed over request, response, tool-argument and tool-result surfaces. |

From the repository root:

```bash
make evaluate-routing
make evaluate-guards
go test -count=1 ./pkg/dataclass ./pkg/inbox ./pkg/trcli ./pkg/qualityeval ./datasets/eval/generate
```

The routing target requires zero class mismatches against the committed baseline.
Expected-label disagreement alone is informational in the current CLI; the focused
fixture test additionally requires every expected class to match and rejects
removed or mismatched baseline rows. Never regenerate the baseline merely to
make a changed classifier pass; review any behavior change and its cases together.

Guard thresholds remain precision **0.98** and recall **0.90**. The positive and
negative examples prevent an always-clean or always-detect detector from passing.
These thresholds apply only to this small corpus. The CLI measures any-hit
binary detection, not correct-category classification or protection against all
attacks. A grouped number with an invalid card checksum can still match another
national-ID format; these controls isolate selected checksum cases rather than
asserting that every invalid card-shaped string is clean. The separate attack
bundle tests cover interchange, tamper rejection and coverage reporting; they do not require complete attack detection. In
particular, passing them does not establish general tool-abuse protection.

## Rebuild the versioned bundles

The two example-set bundles are generated through `datasets.Prepare`,
`BuildSetBundle` / `BuildAttackCorpus`, and `WriteSetBundle`. Their deterministic
creation timestamp is a fixture constant, not a measurement or release time.
No historical request reader, network service or private corpus is used.

```bash
EVAL_OUTPUT="$(mktemp -d)"
go run ./datasets/eval/generate --out "$EVAL_OUTPUT"
cmp datasets/eval/routing_example_set.v1.json "$EVAL_OUTPUT/routing_example_set.v1.json"
cmp datasets/eval/attack_text_cases.v1.json "$EVAL_OUTPUT/attack_text_cases.v1.json"
```

Building the command can download Go dependencies. Generation itself is local.
`generate/main.go` contains the authored attack cases and imports routing cases
from the committed JSONL file. `TestCommittedBundlesReproduce` compares freshly
generated bytes with both committed bundles. Other fixture tests verify digests,
strict import, numeric inventories and tamper refusal; missing files fail.
